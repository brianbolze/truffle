# experiments

Throwaway probes to de-risk a decision **before** committing it to the engine. Each subfolder is dated + named. Not production; not load-bearing. The output that matters is a `FINDINGS.md` that feeds the Frame or the eventual design.

- One folder per experiment: `<YYYY-MM-DD>-<slug>/`
- Standard files: `README.md` (hypothesis + method), the probe (script / recipe), `FINDINGS.md` (what we learned).
- Bulk dumps go in `_out/` (gitignored). Keep READMEs, scripts, and FINDINGS in git.

- [`2026-06-01-coded-queries/`](2026-06-01-coded-queries/) — which consume-side queries earn a *script* vs a `QUERYING.md` recipe? Six probes over the 45-store. Result: only **`find` (alias→key resolver)** and **`relations` (join-check)** are error-prone-by-hand enough to commit as code; count/recent/facet stay one-line recipes. The join-check surfaced three real facts prose can't (plus one false positive): JOIN gap is **23/24 dangling**, top re-capture target is **richemont.com** (in-degree 2: A. Lange + Cartier), a **slug-convention split** in `owns` (`gshock-casio-com` vs `converse.com`); the flagged `salesloft.com`/`clari-com` alias proved a *correct* 2025 merger, not an error (the heuristic can't tell M&A from a typo). Acted on: `scripts/store.py` (`resolve`+`relations`), Casio `owns` normalized, SCHEMA names `canon()` the join key. Battery runs ~1.3s — SQLite stays deferred.
- [`2026-06-04-sqlite-aggregation/`](2026-06-04-sqlite-aggregation/) — probes the parked **rung-3 SQLite** item on the telehealth cohort (the JOIN coded-queries didn't test: the `offerings` one-to-many × `telehealth` cuts, **11/11 dense** vs relations' 1/24). Built `companies⋈telehealth⋈offerings` (555 SKU rows). Result: **stays parked, re-point the trigger.** Speed is a non-issue (build 164ms, query 0.17ms, no-DB Python 9ms); the 3-way JOIN *is* error-prone-by-hand (semaglutide SKUs by `pharmacy_model`; published-vs-gated pivot) but earns **code, not a database** — the useful grouping is `LIKE`=grep (stored `GROUP BY molecule` fragments 8 ways), and coded-queries' precedent graduates such queries into `store.py`, not SQLite. The **price wall is decisive**: `price_num` is *wrong* not lossy (first-month teasers + a $50 consult fee sort above real recurring prices) — a DB launders verbatim discipline into false precision. Recommend a `store.py` offerings long-table reader if the JOIN pull recurs; SQLite only once a real price-normalization layer exists. Engine note: a roster→table loader must be **header-keyed** (eden-health adds `Form`/`Category` cols).
