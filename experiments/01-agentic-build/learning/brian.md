# Brian — learned preferences

Brian's recurring preferences and corrections, learned over time. A **protected lane**, kept out of `lessons.md` so "learn Brian" doesn't dilute into general process lessons. Consult this before proposing process changes or doing judgment-heavy work; an agent that brushes a preference here should heed it, not relearn it.

**Fed by `brian-correction` observations.** When Brian corrects the work, the judgment, or the taste, that's logged as a `kind: brian-correction` observation like any other. A review pass distills the recurring ones into an entry here (a single Brian correction is enough to graduate — it needn't recur).

**Entry format — one `## <slug>` block, terse:**
- **prefers:** the preference, stated as a general rule (no naming a single run/packet).
- **tell:** how it shows up in practice — the move to make, or the reflex to catch.
- **from:** the `brian-correction` observation(s) it was distilled from (links). Grows by *adding* sightings, never rewriting.

Grows slowly — one block per durably-observed preference, never a dump. Retire the way lessons retire: flip, don't delete.

## simplify-dont-just-add
- **prefers:** When improving anything — doc, prompt, rule, code — cut and clarify what's there before adding. A fix that only adds is suspect.
- **tell:** Before any new field / section / rule / helper, answer "what does this replace?" If the answer is "nothing," that's the flag — default to not adding it unless explicitly instructed by Brian. A net-negative diff is a feature, not a failure.
- **from:** [2026-06-23-brian-cut-proposal-fields-9c1b](observations/2026-06-23-brian-cut-proposal-fields-9c1b.md) (+ reinforced in `~/.claude/CLAUDE.md` "Keep it simple — and push back").

## dont-prescribe-from-one-case
- **prefers:** Don't codify, promote, or prescribe an approach from a single site/case. A fix proven once isn't shown to generalize — wait for more cases before making it canonical or baking it into a rule.
- **tell:** When a fix works on the run in front of you, the pull is to promote it (into the canonical script, a Tier rule, an extraction approach). Catch the pull: "how many independent cases has this held on?" One → keep it local and provisional. A cousin of `simplify-dont-just-add` — both are restraint reflexes; this one guards the *evidence* for generalizing, that one guards *additive* scope.
