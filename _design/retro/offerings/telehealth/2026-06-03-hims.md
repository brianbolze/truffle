## Generalizable learnings

**1. For a custom SPA, `robots.txt → sitemap.xml → /map` *is* the backbone — there is no CMS rung.** [recipe · now]
Triggered by: `/products.json` and `/wp-json` both 403 (and don't exist) — hims is a custom React SPA. This
**confirms Eden #1** (branch the ladder on `design_framework`) and completes the matrix: WordPress→`/wp-json`
(AgelessRx), Shopify→`/products.json`, Webflow/SPA→nav + census. New rung worth adding: **read `robots.txt`
first — its `Sitemap:` line is a free, reliable census seed for SPAs** that the rendered grid won't give you.

**2. The `fc.py map --search "site:/path"` slash bug is real and bit again — escalate it.** [recipe · now]
Triggered by: 12 `site:` passes; the `/` in the tag crashes the payload-filename write *after* the API bills.
I lost ~9 credits and ran the passes through the raw map API instead. This is the **second independent hit
(confirms Hone #4)** — two of two broad runs. It's no longer a "documentation nudge"; it's a standing silent
credit leak. One-line fix: slugify `search` in `do_map`.

**3. The controlled Form vocab has real gaps on a *broad consumer* catalog — 5 `[new?]` types.** [contract · later]
Triggered by: chewables (Hard Mints, hair chews), sprays, foam, shampoo, benzocaine wipes — **none have a
Delivery-Mechanisms slug**. This **contradicts Eden's "0 `[new?]`, the vocab covers a real telehealth catalog."**
Eden's clean fit was a *narrow-catalog artifact* (GLP-1 + a few orals); a 7-line brand with OTC + cosmetic SKUs
surfaces genuine holes. Decision for Brian: expand Delivery Mechanisms (chewable/ODT, spray, foam) or accept
`[new?]` as the long tail. Same for Category: `aesthetics-dermatology` is Rx-only by definition, so 4 OTC skin
basics had nowhere clean to land (`[?]`).

**4. "Indexed level" needed active judgment the lint can't see.** [contract · validate]
Triggered by: `/labs/biomarkers/*` exposes **70+ leaf pages**, one per biomarker — all sub-indexed *content*,
not SKUs. The indexed level is the one $349/yr panel + the Galleri add-on (2 rows, not 72). **Confirms
AgelessRx #5** (dedup is judgment the lint can't enforce) and extends it from marketing-URL families to
**content-leaf exclusion**. A naive enumerator inflates this line 35×.

**5. The prompt assumed a CMS backend that a custom SPA doesn't have.** [prompt · now]
The run prompt said "cross-check a CMS backend (`/wp-json`, `/products.json`)." For hims that's a dead end.
The recipe already knows to branch on framework (Eden #1) — the *prompt* should defer to it, not hard-code a
CMS probe.

## The call I'm least sure about — and it's the cross-brand crack

**6. Visibility is being applied *inconsistently across runs*, and I'm part of the divergence.** [contract · now+later]
I marked hims's ED "From $4/use" / "From $22/mo" floors **`published`** — reasoning the entry tier is itself
purchasable and the *only* mandatory-separate-cost line is weight-loss (membership). **But the run prompt's own
`partial` triggers list "a floor that moves materially with dose/tier"** (sildenafil 25/50/100mg *does* move),
and **Hone #6 marked exactly that From-$X pattern `partial`.** So the same pricing shape got **published (me)
vs partial (Hone)** — the precise cross-brand inconsistency this triage hunts. My honest read: I under-applied
trigger (c) and over-weighted "is there a separate fee." Eden #4 already flagged that visibility is brand-shaped;
this run shows that's not benign — it's producing **opposite tokens for the same mechanic**. The contract should
either (a) pin a single decision tree (separate-mandatory-cost = the *only* partial trigger; dose-floors =
published-with-floor-quoted), or (b) explicitly bless that the token is approximate and cross-brand consistency
is query-time only. Right now three runs have three rulings and that erodes the token's comparability.

**Also possibly wrong (smaller):** I rostered **"Sertraline for PE"** as a SKU, but its URL resolves to the PE
*storefront*, not a distinct PDP — likely a nav entry, not a buyable. A verify-the-slug-resolves step before
rostering footer links would've caught it. And **chewable → `[new?]`** vs folding it into `pill` (oral route) is
a genuine coin-flip I called toward flagging.
