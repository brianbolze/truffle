# Retro — offerings module, Eden run (2026-06-03)

An early `offerings.md` run, and the **first to use the extended 9-column shape** (adds `Form` + `Category`
slug columns keyed to the Notion Delivery-Mechanisms / Product-Categories vocab). The artifact landed clean —
[`store/eden-health/offerings.md`](../../../store/eden-health/offerings.md): 27 buyable + 6 family rows, 25 PDPs,
27 credits, lint-pass. This captures what generalizes, not Eden trivia.

## What worked — keep doing

1. **Completeness via *blind-source agreement*.** The homepage mega-nav and the `/map` census independently
   returned the **same 25 `/treatment/*` URLs**. That exact agreement between two methods that don't see each
   other is what licenses a "complete" claim — stronger and cheaper than either alone. Generalizable: don't just
   run the census as insurance (the Hone lesson), *reconcile* it against the nav and report the agreement as the
   completeness signal.

2. **Page-attested molecule discipline paid out again, finer.** Recorded Wegovy→semaglutide and
   Zepbound→tirzepatide (both "contains" statements), but **Ozempic→"not stated"** and **Mounjaro→"not stated"**
   — neither names its molecule in product copy. The grep-the-price lint held throughout.

## Generalizable learnings

**1. The enumeration backbone is platform-dependent — branch the ladder on framework.** *(→ recipe)*
The AgelessRx retro added a CMS-REST rung (WordPress `/wp-json`, Shopify `/products.json`). Eden is **Webflow**,
which has **no public catalog API** — so that rung simply doesn't exist here, and nav + `/map` census *is* the
authoritative backbone, not a fallback. The profile already records `design_framework`; read it first and pick:
WordPress/Shopify → REST registry is the hero (AgelessRx); Webflow / custom SPA → nav + census is the hero
(Eden). Same question every run — *where does the real catalog live?* — different answer by platform.

**2. Citation-title attestation ≠ product attestation — a finer molecule trap.** *(→ capture rules)*
Ozempic's page contains the word "semaglutide" — but only inside a **reference-list citation** ("Clinical Review
Report: Semaglutide (Ozempic)"), never as a "contains" statement. Recorded "not stated." This is the alt-text
trap (Maximus/Hone) one level subtler: a molecule can appear in *page text* yet not be *attested to the SKU*.
Scope attestation to **product copy**, and explicitly exclude citations, ISI/footnotes, and SEO blocks.

**3. "Configurator" PDPs yield multiple buyables under one slug.** *(→ contract, minor)*
Eden's flagship `/treatment/glp-1-treatments` is a hub that sells **two compounded sub-SKUs** (Semaglutide $99,
Tirzepatide $199) with no own URL, *and* lists 4 branded SKUs that do have URLs. Handled by rostering the
sub-SKUs as distinct buyable rows sharing the hub slug with a "(sub-SKU on this page)" note. Generalizable: a
pick-your-molecule configurator → multiple rows keyed to the shared slug; don't collapse to one, don't invent
slugs.

**4. Visibility is a *stated, brand-shaped* judgment — Eden adds a new "why."** *(→ contract)*
Three brands now, three different reasons for the same `partial` token: Hone (dose tiers move the floor), Hims
(mandatory membership), Eden (mandatory membership **+** intro-only "first month" rates with the recurring price
withheld). Eden even *removes* Hone's leg via its "Same Price at Every Dose" guarantee. The crystallized rule:
**`partial` = the all-in isn't fully shown; quote the *why* verbatim, because the mechanism is brand-specific.**
This validates the Hone retro's request to document the visibility rule inline (overview + anchor).

**5. Site-wide boilerplate ≠ SKU-specific truth.** *(→ capture rules)*
The membership footnote sits on *every* PDP — including the non-Rx Cell Theory supplement, where it's generic
boilerplate that arguably doesn't apply (no asterisk on the hero price; the page carries a dietary-supplement
disclaimer instead). Before trusting a footnote, check it's **hero-attached** (an asterisk on the price), not
just present in the footer.

## The 9-column shape — lint-compatible, by prefix luck

The new `Form`/`Category` columns inserted between `Visibility` and `What` **passed the existing lint unchanged**.
Why: the lint resolves spine columns by `startswith` prefix, and neither "form" nor "category" collides with a
spine prefix (nor equals "molecule"). All 6 page-attested forms mapped to existing Delivery-Mechanism slugs
(**0 `[new?]`**) — the controlled vocab covers a real telehealth catalog. Five `[?]` category calls (Glutathione,
MIC+B12, NAD Face Cream, Cell Theory, Everyday+) were genuine cross-cutting tensions, flagged not forced.
**Caveat to document:** the lint doesn't yet *validate* Form against the DM slug set or Category against the
Product-Category set — a typo'd slug would pass silently. If the 9-column shape is adopted into the contract,
add a closed-set check for both columns. *(→ lint)*
