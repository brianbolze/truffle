# Retro — offerings module, IDEO run (2026-06-04)

The **pure-bespoke floor**: a design/innovation consultancy (`offering_category: Services / Consulting`, `portfolio_shape: Flagship + companions`), zero published prices, zero enumerable SKUs. Guided run requested "all modules" incl. `offerings.md` + hero-images; **I declined to write the file** and carried the offering shape in `profile.md`'s *What they offer* (6 lines, all `[on-request]`). This retro is the no-write case — what the spine binds to when nothing is priced.

- **The spine didn't strain — it idled (simulated, not written).** Walk the columns for IDEO and every load-bearing cell goes inert: **Price (verbatim)** → `—`/none on 100% of rows (nothing published); **Visibility** → `on-request` on every row — a closed set collapsed to one value does *zero* discriminating work, the opposite of its telehealth job; **Slug** → service-area pages (`/health`, `/ai`, `/design-services`) are positioning URLs, not within-company SKU keys, so the key is fiction; **`molecule · form · access` lead** → null on all three (no molecule, no form, no purchasable access). Airbnb/Notion *stretched* the spine with non-SKU content; IDEO leaves it **structurally valid but semantically empty** — a roster that re-encodes the nav with blank price/visibility columns.
- **Added nothing — the right add was the decline itself.** No file, no columns. The generalizable artifact is the **declared non-fit**: recorded in `profile.md` Provenance `Run profile` ("offerings.md / hero-images skipped — no per-SKU grain, no sellable flagship to render; family-line breadth is the altitude"). That decline-with-reason should be a **first-class, repeatable outcome**, not a per-run judgment call re-litigated each time.
- **OFFERINGS.md silent at the exact floor.** "When to write it" gates on **consumer-pull** ("a cohort's consumer needs the grain") and says *default elsewhere is don't write it* — but it never names the **hard floor**: a shape with no priced, enumerable SKU *at all*, where the schema has nothing to bind even if a consumer asked. The doc tells you the file is opt-in; it doesn't tell you it's *impossible* for services. Worse, the **guided pre-flight (skill step 2.5) offers "+ per-SKU offerings.md" unconditionally** — no shape guard — so a user can request a file the contract would have you not write. That conflict (user-requested vs. shape-can't-hold) is **unadjudicated**; I resolved it by declining, but the next agent gets no steer.
- **One change — push the guard upstream, one clause each.** (a) OFFERINGS.md "When to write it": add a **Floor / non-fit** line — *pure-services / bespoke-engagement companies (`Services / Consulting`, no published price, no enumerable SKU) → don't write it even on request; `profile.md`'s What-they-offer + `[on-request]` tokens are complete; record the decline in profile Provenance.* (b) Mirror in the skill's guided menu: **gray-out / warn the offerings options when the resolved `offering_category` is `Services / Consulting`** (or unknown-but-no-pricing), so the menu stops offering a structurally-empty module. Cheaper than every services run re-deriving the decline.
- **Verdict: didn't fit, didn't force it — correct decline.** As the pure-bespoke floor the module **collapses, it doesn't degrade gracefully** — one-value Visibility, empty Price, fictional Slugs, null `molecule·form·access` = a positioning list the spine can't hold, strictly dominated by the `profile.md` lines that already exist. The **opt-in gate worked**; the only real gap is that the *guided menu can still offer it*, so the fix belongs at the menu + a floor clause, not in the roster schema.
